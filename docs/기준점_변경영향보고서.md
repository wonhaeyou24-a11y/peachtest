# CHANGE IMPACT REPORT — 시설물 기준점(시점·종점) 기능 (v106)

## 1. 목적
손상 위치를 "시설물 시점에서 몇 m"로 구하기 위한 기준점(시점·종점·중간점)을 현장에서 GPS로 찍어 시설물에 저장한다.
계산·표시는 피치샷 데스크에서 하고, 웹앱은 **현장 입력(기준점 저장)만** 맡는다.

## 2. 변경 내용 (최소 패치)
| 위치 | 변경 |
|---|---|
| `#facilityModal` HTML | "📍 기준점" 구역 추가(정보 수정 때만 표시) |
| 새 함수 블록 (`openFacilityModalForEdit` 바로 앞) | `refPoints` 읽기/그리기/측정/삭제 — 전부 새 함수 |
| `openFacilityModalForCreate` | 구역 숨김 1줄 추가 |
| `openFacilityModalForEdit` | `renderRefPoints(site)` 호출 1줄 추가 |
| `PS_BUILD` / `service-worker.js` CACHE_NAME | v105 → v106 |

### v107 추가: 지도에서 직접 지정 (GPS가 안 잡히는 곳용)
- 정보 수정 창에 "🗺 시점/중간점/종점 지도에서 지정" 버튼 3개 추가. 누르면 창이 닫히고 해당 시설물의 지도 모드로 가서 "지도에서 ○○ 위치를 눌러주세요" 배너를 띄운다.
- 기존 지도 클릭 처리(`leafletMap.on('click')` 지점 만들기)는 **수정하지 않았다.** 지정 중일 때만 `#mapStage`의 클릭을 capture 단계에서 먼저 받아 막고(기존 지점 만들기로 안 넘어감), 지정이 끝나면 원래 동작으로 돌아간다.
- 18단계 이상 확대해야 눌러진다(미만이면 안내만 하고 저장하지 않음). 오차 추정 = 화면 1픽셀의 실제 거리 × 8픽셀. 지도 자체의 위치 오차는 포함되지 않는다.
- 저장 형식은 GPS 측정과 같고 `source:'map'`, `zoom`이 더해진다(GPS 측정은 `source:'gps'`, 옛 기록은 필드 없음 = GPS).
- 다른 시설물을 지정하면 "전환"과 같은 순서(`commitLiveToCurrentSite` → `loadSite` → `saveState`)로 연다.
- 취소하면 아무것도 바꾸지 않고 정보 수정 창으로 돌아온다.

## 3. 데이터 구조 (스키마 변경 없음)
`site.refPoints = [{ id, role:'start'|'mid'|'end', label, lat, lng, accuracy, spread, samples, quality, recordedAt, deviceId }]`
- `site`(시설물) 객체의 새 필드. DB 컬럼 추가·마이그레이션 없음. `ps_facilities.data`(JSON)에 그대로 실려 올라간다.
- 필드가 없는 기존 시설물은 `refPoints` 없이 그대로 동작(읽을 때 `|| []`).

## 4. 건드리지 않는 보호 대상
`storageGet/Set`, `openIDB`, `idbPut*`, `commitNewMarker`, `loadState/loadSite/saveState/performSaveState`,
`commitLiveToCurrentSite`, `pushProjectToCloud`, `pullEntityChanges`, `syncSingleEntity`, `queueCloudSync` — **수정 없음**.
기존 함수는 `saveState()` / `queueEntitySyncForFacility()` / `iOwnFacility()` / `haversine()`을 **호출만** 한다.

## 5. 위험 검토
| 위험 | 판단 |
|---|---|
| 저장 | `commitLiveToCurrentSite`는 지정된 필드만 덮어써서 `refPoints`를 지우지 않음 |
| 클라우드 올리기 | `facilityMetaSignature`가 모든 비제외 필드를 지문에 넣어 변경이 자동 감지됨. 현재 시설물이 아닐 수 있어 `queueEntitySyncForFacility(site)`를 직접 호출 |
| 클라우드 가져오기 | `Object.assign({}, local, cloud.data)` — 클라우드에 `refPoints`가 없으면 로컬 값 유지. 올리기 대기 중이면 pull 보호가 작동 |
| 팀원 시설물 | 시설물 행은 만든 사람만 올림 → 팀원이 찍은 기준점은 이 기기에만 저장되고, 화면에 그 사실을 안내 |
| 데이터 손실 | 삭제는 사용자가 명시적으로 누른 기준점 1건만. 실패해도 자동 삭제 없음 |
| 오프라인 | 측정·저장은 전부 기기 안에서 처리(네트워크 불필요) |
| 사진 촬영 체인 | 무관(사용자 제스처 흐름을 건드리지 않음) |
