## 0. 한눈에 보기

```
[전차자료정리 스킬] organized.json(시설물별) + 손상사진 zip + 외관망도
        │  ① 가져오기 (프로젝트·시설물 자동 생성)
        ▼
[PeachShot 앱] 시설물별 "조사준비 완료" 상태
        │  ② 현장: 전차손상 체크리스트 + 전차사진 확인하며 조사
        ▼
[PC 데스크] ③ 전차 ↔ 금회 나란히 보며 수정·보완 + 현장시험 입력·산출
        │  ④ 내보내기 번들
        ▼
 보고서 작성 / 금회 외관조사망도 / 현장시험 부록 엑셀
```

| 단계 | 이미 있는 것 | 부족한 것 | 규모 |
|---|---|---|---|
| ① 프로젝트 자동 준비 | 새 프로젝트·시설물 일괄 생성·도면 일괄 등록·기존손상 엑셀 가져오기 | 스킬 JSON 읽기, 전차 이력, 전차 사진·도면 연결 | 중 |
| ② 전차손상 보며 현장조사 | 지점의 손상기록에서 기존손상 선택 → 내용 복사 + 기존/현재 비교 | **전차 사진이 현장 화면에 안 나옴**, 전차손상 중심 체크리스트·진행률 없음 | 중 |
| ③ 데스크 편집 + 현장시험 | 손상현황 통합표(기존+변화+신규), 손상비교 Excel | 나란히 편집 화면, **현장시험 입력·산출 전체 신규** | 대 |
| ④ 내보내기 | Word·Excel 출력들 | JSON 번들(통합계획 8단계), 금회 외관조사망도용 위치 데이터, 시험 부록 엑셀 | 중 |

## 2. ① 전차자료 → 프로젝트·시설물 자동 준비

**목표**: 스킬 결과를 가져오면 프로젝트와 시설물이 만들어지고, 각 시설물이 "조사준비 완료" 상태가 된다.

### 2-1. 가져오기 흐름
1. `새 프로젝트 만들기` 화면에 **"전차자료로 프로젝트 만들기"** 추가: 프로젝트명 입력 + `organized.json` 여러 개 선택 (+ 사진 zip, 외관망도 파일 선택)
2. 미리보기: 시설물 N개 / 시설물별 제원·전차손상 수·사진 수·확인필요 수 → 확인 후 생성
3. 생성: 프로젝트 1개 + 시설물 N개(+ 전차 이력·손상·사진·도면)
4. 이미 있는 프로젝트에도 "전차자료 추가 가져오기" 가능 (시설물 매칭 규칙 아래)

### 2-2. 매핑
| organized.json | 앱 위치 | 비고 |
|---|---|---|
| `facility` 의 관리번호(예: 192127), 시설물명 | 시설물 `name` + 신규 `facilityNo` | 매칭 키: 관리번호 → 없으면 시설물명 |
| `compare` (관리대장 값) | 연장·높이·준공년도·노선·주소 | 대장↔전차가 다른 항목은 **덮어쓰지 않고** 확인필요 표시 |
| `inspection_history`, `prior_evaluations`, `repair_history` | 신규 `site.history` (읽기 전용) | 원문 그대로 |
| `prior_damages` | `existingDamages[]` | 아래 표 |
| `quantities`, `issues`, `field_tests` | 신규 `site.priorRef` (읽기 전용 참고자료) | 통합표·검수·시험 부록 비교열에 사용 |
| 손상 사진 zip (`사진 파일`명) | 기존손상 `photos[]` | 아래 3-2 용량 처리 |
| 외관망도 도면 | 시설물 `drawings[]` 중 **"전차 외관망도"로 표시** | 금회 도면과 구분 |

**`prior_damages` → 기존손상**
| organized.json | 기존손상 필드 |
|---|---|
| `손상명` | `damageName` |
| `위치(m)` | `drawingPosition` |
| `구성요소` | `component` (소제목 번호 접두사는 원문 유지) |
| `규모` | `measurement` (원문 문자열) |
| `전차 보수·보강방안` | `repairMethod` |
| `사진 파일` | `photos[]` |
| `출처` | 신규 `sourceRef` (원문 출처 보존) |
| (스킬에 없음) | `section`(구간)은 비워 두고 데스크/체크리스트에서 보완 |

### 2-3. 조사준비 상태 (시설물 목록에 표시)
시설물마다 준비 체크: 제원 ✓ / 전차 이력 ✓ / 전차손상 N건 / 전차사진 M장 / 도면 ✓ / 확인필요 K건. 부족한 항목은 PC 준비 화면(이미 있음)의 "도면 없는 것만 보기"와 같은 방식으로 필터.

### 2-4. 현장 투입 전 오프라인 준비
전차 사진은 현장에서 열려야 하므로 **"현장용 저장"**(사진을 기기 IndexedDB에 미리 내려받기) 단계가 필요하다. 이미 있는 오프라인 사진 저장(`photoBlobs`) 구조를 사용하고, 시설물별 용량을 표시한다.

## 3. ② 전차손상을 보며 하는 현장조사

**목표**: 시설물을 열면 전차손상이 목록으로 나오고, 전차사진·전차 내용을 보면서 확인하고, 금회 값을 입력하면 자동으로 전차손상과 연결된다.

### 3-1. 현재 흐름과의 차이
- 현재: 현장에서 지점을 찍고 → 사진 → 손상기록 → "기존손상 연결"을 선택(목록에서 찾음). **전차 중심이 아니라 금회 지점 중심.**
- 제안: **전차손상 체크리스트를 현장 화면의 별도 탭/패널로 추가**하고, 지점 중심 흐름은 그대로 둔다 (기존 동작 불변).

### 3-2. 전차손상 체크리스트 (신규 패널)
- 정렬: 구간 → 위치(m). 필터: 미확인 / 확인함 / 변화 있음 / 소실.
- 항목 한 줄: `[번호] 구간 · 위치 · 손상명 · 전차 규모` + 상태 배지 + 전차 사진 섬네일
- 진행률: "전차손상 18건 중 11건 확인" (기존 `needsReviewCount` 계산을 확장)
- 항목을 누르면 **상세**: 전차 사진(확대, 여러 장 넘기기) + 전차 원인·보수방안·출처 + 전차 외관망도 위치 보기
- **버튼 "이 손상 조사하기"**: 금회 지점·손상기록을 만들고 `existingDamageId`를 **미리 연결**한 채 카메라로 이동. 전차 규모는 이미 규모 입력칸에 시드(기존 `seedMeasurementItemsFromText` 재사용). 조사자는 달라진 값만 고친다.
- 변화상태 선택(동일/증가/감소/보수됨/소실)을 한 번 탭으로. 소실·보수는 지점 없이 상태만 기록 가능해야 한다 (현재는 지점이 있어야 연결됨 — 확인·보완 필요).
- 전차 목록에 없는 새 손상은 지금처럼 일반 지점으로 추가 → `신규`.

### 3-3. 현장 화면에서 전차사진 보기 (현재 빠져 있는 부분)
- 지점 손상기록의 "기존 vs 현재 비교" 카드에 **전차 사진 섬네일** 추가 (연결된 기존손상의 `photos[]`).
- 카메라 촬영 화면에서 **전차 사진을 반투명 겹쳐 보기/나란히 보기** (같은 각도로 재촬영) — 후순위 선택 기능.

### 3-4. 전차 위치를 도면에 표시 (선택, 환산 가능 여부 먼저 확인)
전차 외관망도를 도면으로 올리고 손상의 `위치(m)`를 도면 좌표로 환산하면 도면에서 전차손상 위치를 볼 수 있다. 눈금 보정 값에서 연장(m)↔도면 좌표 환산이 되는지 코드 확인이 필요하다. 안 되면 체크리스트 중심으로 먼저 진행한다.

## 4. ③ 데스크: 수정·보완 + 현장시험 부록

### 4-1. 전차 ↔ 금회 나란히 편집 (신규 화면)
- 행 = 전차손상 1건(+ 연결된 금회 손상). 열 = 전차(규모·원인·방안·사진) | 금회(규모·원인·방안·사진) | 변화상태 | 증감(자동) | 비고.
- 신규 손상(연결 없음)은 별도 구역. 전차 손상 중 **금회 미확인**은 상단에 경고.
- 사진은 전차·금회를 나란히 확대해 보고, 금회 사진을 다른 지점에서 옮겨 붙일 수 있게.
- 편집은 같은 데이터(지점·손상·기존손상)를 직접 수정. 이미 있는 손상현황 통합표(`buildDamageInventory`)를 화면 데이터원으로 재사용.

### 4-2. 현장시험 입력·산출 (신규 모듈) — **가장 큰 개발 항목**
- 데이터: `site.fieldTests[]` (시험 종류, 시험 개소/측점별 입력값 격자, 산출값, 전차 값 참조).
- 시험 종류(스킬 `field_tests` 분류 기준): 재료시험 현황 / 계획선형오차 / 수준측량 / 선형측량 / 반발경도(슈미트해머) / 토질(연경도·표준관입·토양경도) / 염화물·탄산화 / 불연속면 / 암반 강도·평가.
- 각 시험 = **입력 격자 + 산출식 + 출력 표**. 예: 반발경도 → 타격값 입력 → 평균·보정(재령보정계수 등) → 추정압축강도. 계획선형오차 → 측점별 측정 기울기 → 오차.
- 전차 값(`priorRef.field_tests`)을 **'17년/'23년/금회** 같은 시기별 열로 나란히 표시 (전차 표 구조를 유지).
- 산출 결과는 **부록 엑셀**로 내보냄 (4번 내보내기 참조).
- 현장에서도 입력 가능해야 하는지(수치를 현장에서 불러주는 경우)는 결정 필요 — 우선은 PC 데스크 입력.
- **필요한 정보(결정사항 7장)**: 시험 종류별 부록 엑셀 양식(기존 보고서 부록 샘플)과 산출식(어느 지침·식을 쓰는지).

### 4-3. 데스크 검토 보조
확인필요(`issues`)와 누락 점검(사진 없는 지점, 규모 미입력, 전차 미확인, 시험 미입력)을 한 화면에서 확인. 모든 AI/자동 판정은 "후보"로 표시하고 최종 확정은 사람이 한다.

## 5. ④ 내보내기

### 5-1. 내보내기 번들 (통합계획 8단계)

## 7. 위험과 주의

1. **동기화 소유권**: 팀원이 올린 지점·기존손상을 다른 사람이 데스크에서 고치면 클라우드에 반영되지 않을 수 있다(`not-owner`). 전차자료 가져오기는 **프로젝트 담당 한 명**이 하도록 운영 규칙을 정하거나, 데스크 수정이 필요한 범위를 정하고 2기기 실측 후 코드 변경 여부를 판단한다.
2. **도면·사진 용량**: 도면은 시설물 blob에 이미지째 저장되고, 전차 사진까지 더하면 크다. 전차 사진은 축소본으로 저장, 원본은 필요 시. 시설물별 용량 표시.
3. **회귀 보호**: 보호 함수(`pushProjectToCloud`, `syncSingleEntity`, `loadState` 등)는 건드리지 않고 새 함수·새 화면 위주로 추가. 변경 전 CHANGE IMPACT REPORT, 후 REG-01~30.
4. **원문 불변**: 가져온 전차 값은 읽기 전용 이력으로 보존. 금회 입력과 섞이지 않게 하고, 금회 값은 복사본에서만 수정.
5. **손상명 표기**: 스킬의 손상명과 앱 표준(`STANDARD_DB`)이 다르면 비교표 매칭이 깨진다. 가져올 때 원문 유지 + 표준명 후보 제시.
6. **전차 위치(m)→도면 좌표 환산**은 아직 검증하지 않았다 (3-4). 안 되면 도면 표시는 후순위.
7. **현장시험 산출식**: 잘못된 식은 보고서 오류가 된다. 산출식은 사용자가 확정한 지침·기존 부록 엑셀 기준으로만 구현하고, 구현 후 기존 보고서 값과 대조 검증.

| 피치샷 데스크 | 정리·확정·계산·내보내기 전부(아래) |
| 외관분석(통합)프로그램 | 도면(DXF) → 종합보고 엑셀(손상현황·요약·전차비교), 상태평가(보강토 옹벽), 강우량 표 |

### 11-2. 데스크에서 새로 된 것
- **현장시험**: 탄산화, 계획선형오차, 수준측량, 반발경도(보강토옹벽·콘크리트·암반), 토양경도, dip 가져오기, 부록 엑셀. 옹벽 시험값은 "상태평가 측량값 엑셀"(Span별 최대 침하·선형오차, 진행성)로 외관분석프로그램 상태평가에 넘길 수 있다.
- **상태평가**(메뉴 보고서 > 사면 상태평가, Ctrl+Shift+E):
  - 사면(파쇄암반·절리암반·연약암반·토사): f1(손상상태/24), f2(파괴요인/종류별 분모), F, 구간 등급, 시설물 등급=구간 최대. 손상상태 d·e(f1 0.55 이상)는 조정 불가한 중대한 결함 → f1 적용.
  - 옹벽(보강토 분모 76/79, 콘크리트 73/61 등): 구간 F, 시설물 등급=구간 평균. 보강토 전면부 진행성 배부름 d·e는 중대한 결함 → 구간 0.749/1.000, 시설물은 구간 최대. 13.1.4 중대한 결함 경고, 복합식(보강토+콘크리트 혼합) 경고.
  - 계산식은 사용자 샘플 엑셀(사면 8개 17구간, 옹벽 9개 113구간)과 전부 일치하고, 세부지침 13·14장 배점·분모·기준과 대조를 마쳤다.
  - 엑셀 출력(샘플 양식, 수식). 점수는 항상 기술자가 확정한다.
- **강우량**: 기상청 "일 최다 강수량"(.xls/.xlsx/.csv) 가져오기 → 외관분석프로그램과 같은 3분할 표·누년 평균(울산 152: 1996~2025, 134.6mm) → ⑨ 강우량 등급, Word·Excel 표.
- **자동 제안**(확정은 사람): 사면 ④ 발생규모(손상 목록 또는 도면 집계 물량), 사면경사(평균각도), ⑦ 절리상태(dip 평균), ⑨ 강우량(누년 평균). 옹벽 ① 침하·② 선형오차(현장시험 측량값), ⑥ 이격·⑦ 유실·④ 세굴(도면 집계 Span별 개소, 돌출은 이격으로 우선 처리). 실제 옹벽 도면 26구간 대비 이격 24, 유실 25 일치.
- **보고서 초안(Word)**: 상태평가·강우량이 샘플 목차 위치에 자동 삽입된다. 사면은 "4.2.7 과업구간 기상청 강수량 분석"(4.3.3 앞), "4.5 상태평가"(4.7 앞), 옹벽은 "상태평가"(전차 비교 뒤, 보수·보강 앞). 위치를 못 찾으면 맨 끝 부록.

### 11-3. 엔진(inspection-engine 1.3.0) 보완
- **시설물 키**: 어떤 시설물명에서도 키를 만든다. km 표기는 소수 3자리로 맞추고(14.51K → 14_510), km 없는 이름은 이름 자체가 키(고성절토사면). 기존 3자리 키는 그대로.
- **통합프로그램 새 양식**(요약·SPAN·전차비교가 수식으로 자동 계산) 지원: 편집기의 손상 행·요약(구분·대책)·전차 비교 편집이 저장에 반영되고, 수식 시트는 다시 쓰지 않는다. 편집이력의 수식 글자 때문에 Excel 이 파일을 못 열던 문제도 수정했다.
- 데스크 `engine/` 의 exe 가 `종합자동화/dist` 보다 오래돼 있던 것을 교체했다(이전 파일은 `_rollback_fieldtests`).

### 11-4. 실제 파일로 확인한 흐름
고성 DXF(사면)·옹벽 DXF(7개 시설물) → 종합집계 → 도면 집계에서 제안 → 상태평가 → 보고서 초안(엔진) + 상태평가·강우량 삽입 → Word 열림 확인(`test/rehearsal_report.js`). 클라우드 내려받기·웹앱·dip 구간은 이 PC에서 재현하지 못했다.
